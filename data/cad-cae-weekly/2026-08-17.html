执行摘要

本周最值得投入验证资源的不是“再接一个生成式 CAD 模型”，而是把装配、参数扰动与求解结果一起纳入可执行验收。FreeCAD 周构建加入 RigidGroup，为成组零件的相对位姿锁定提供了原生对象；CADEngBench 则用 B-Rep、STEP 重导入、参数扰动、精确装配配合与 CalculiX 复算揭示：看起来像 CAD 的结果，常常仍不是可用工程模型。

  • FreeCAD：weekly-2026.08.12 是测试用预发布；RigidGroup 已合并，但仍缺少公开性能基准，应先做保存/重载、激活/停用、求解器与下游 MBD 导出的回归测试。
  • AI × CAD/CAE：CADEngBench 覆盖 300 个参数化零件、600 项生成/编辑任务，以及 150 组装配体对；领先闭源模型的有效 B-Rep、工程约束和 FEA 一致性仍存在明显落差。
  • 互操作与后处理：rhino3dm 修正 Python/JS 双精度网格顶点路径；VTK/ParaView 修复文件探测内存占用、数组形状比较和批量截图泄漏，直接影响大模型自动化流水线的稳定性。
  • IGA：本窗口未核验到 G+Smo、GeoPDEs、PetIGA、tIGAr 或 igatools 的正式发布/已合并重要变化；本周应继续把 OCCT 的精确 NURBS 与修剪边界提取作为验证工作，而不是把旧成果包装成新闻。

本周最优先的 3 项行动

  1. 给 FreeCAD RigidGroup 建一个最小回归夹具。选择三件以上带局部坐标系的零件，创建刚性组后分别执行移动、停用/激活、保存/重开和装配求解；记录每对零件相对变换的平移误差与旋转误差，并检查 MBD 导出是否把刚性组误识别成额外自由度。
  2. 把 AI 产物验收升级为 L0—L3 门禁。L0 检查脚本可执行、B-Rep 有效和 STEP 重导入；L1 检查尺寸、拓扑与基本制造约束；L2 对关键参数做扰动并执行指定编辑；L3 用同一网格/材料/边界条件跑 CalculiX，对位移、应力分位数和柔度做成对比较。
  3. 加入大坐标网格与长时批处理测试。用 3DM 双精度网格跨 Python/JavaScript 往返，测最大坐标误差；同时循环执行 ParaView CaptureWindow，观察 RSS 增量与图像哈希，避免精度损失或内存泄漏在夜间任务中积累。

FreeCAD Assembly 自动化与 API/插件变化

RigidGroup：原生锁定多组件相对位姿

FreeCAD PR #29605 于 8 月 10 日合并，新增专用 RigidGroup 对象、任务面板及激活/停用逻辑。其工程价值在于：一组紧固件或预装子组件可以保持当前相对位姿，而不必为了表达“刚性”重排装配树。最终实现使用 PropertyPlacementList 保存成员位姿，而非序列化 JSON；这有利于属性系统、保存和脚本访问，但公开材料没有给出大规模装配的求解时间或内存基准。

建议实验：用 3、30、300 个成员形成三个规模档，分别测试创建、拖动、求解、保存/重载和停用/激活；以成员间相对变换闭合误差、文档重算时间和峰值内存为指标。若导出到动力学求解器，还应确认刚性组被折叠为单刚体或显式刚性约束，而不是产生重复质量和隐藏自由度。

周构建与自动化健壮性

weekly-2026.08.12 是面向测试的预发布，不应直接替换生产环境。本周还合并了属性编辑器浮点精度修复 #29315、可翻译且更细分的文件异常类型 #26775，以及 TechDraw 避免对低阶 B-spline 做不必要三次近似的 #29648。自动化脚本应测试小数点/逗号区域设置、科学计数法往返，并优先按异常类型处理只读、路径与权限错误，减少对英文错误字符串的脆弱匹配。

IGA / CAD–分析一体化

本周无重要变化。在固定窗口内，对 G+Smo、GeoPDEs、PetIGA、tIGAr 和 igatools 的官方仓库检索未发现可归入本期的正式版本或已合并重要变化；因此不复述窗口外的既有论文或功能。

面向 FreeCAD/OCCT 的本周验证边界仍然明确：从 STEP/OCCT 中保真提取曲面次数、控制点、节点矢量、权重、参数域、周期性、外环/内环修剪曲线与 pcurve，并逐面对比重构后的几何偏差和连续性。对 trimmed/immersed IGA，应记录切割单元比例、积分点数量、条件数、预条件迭代数、自由度、位移/模态误差、组装/求解时间和内存；局部加密则区分 THB-spline、LR-spline 与传统 h-refinement 的自由度收益。

最小对照：同一修剪 NURBS 薄壳分别走 IGA 与“Gmsh 网格—CalculiX”传统 FEM，统一材料、载荷和边界条件，比较静力位移、前六阶固有频率、几何逼近误差和总耗时。只有几何保真、边界施加与积分稳定性都通过，才能把“无网格几何转换”转化为真实工作流收益。

AI × CAD/CAE

CADEngBench：从“像 CAD”转向“能工作”

8 月 10 日提交的预印本 CADEngBench 建立了参数化设计、装配推理和物理仿真的联合基准。参数化部分包含 300 个零件、600 个从零生成/功能编辑任务；其中 164 个零件带线弹性 FEA 测试。装配部分含 150 组刚体对，报告中的模型比较使用 120 组，要求精确定位 B-Rep 面/边、预测关节类型和坐标框架，并用 PyBullet 检查运动。

L3 使用 Gmsh 二次四面体与 CalculiX，在参数族上比较 95 分位 von Mises 应力、最大位移、柔度与应力集中，并取最差对数比。结果表明“能导出 STEP”远非完成：工程约束、参数鲁棒性和物理响应会继续筛掉大量候选。论文也有边界：材料、容差和工况来自有限公开描述；L1 不是制造认证；每项只覆盖一个参数和一次有界编辑。本次检索未在论文页面确认官方代码/数据仓库，故开放性暂记为论文与补充材料公开、代码数据未确认。

迁移方案：把 FreeCAD 宏、FCStd 与 STEP 作为 L0 工件；将尺寸/拓扑/装配约束写成 L1 断言；对关键 Spreadsheet 参数做 L2 扰动；最终复用固定 Gmsh/CalculiX 输入模板完成 L3。失败必须落到具体层级，不能只汇总成“生成成功率”。

CATIA 与 Rhino / STEP / 3DM 互操作

rhino3dm PR #734 于 8 月 13 日合并，修正 Python/JavaScript 绑定在有效双精度顶点数组存在时仍返回 float32、写顶点只更新单精度数组，以及清空网格后双精度数据残留的问题。新增的 Point3d 访问与数组接口让大坐标或紧公差网格不必隐式降精度。

验证实验：在 106 量级坐标叠加 10−4 尺寸扰动，执行 3DM→Python→JavaScript→3DM 往返；记录最大绝对/相对坐标误差、网格有效性、顶点数和内容哈希。该变更只针对网格顶点路径，不能外推为 NURBS/B-Rep 或 CATIA 语义互操作的全面提升。本窗口未核验到 CATIA/STEP 官方格式或 API 的重要发布。

Gmsh 与 meshio

本周无重要变化。Gmsh 官方稳定版仍为 4.15.2；meshio 官方仓库窗口内未发现已合并重要 PR 或新发布。工程上宜冻结现有版本，并把 CADEngBench 的“二次四面体—CalculiX 成对复算”思路用于网格回归：固定几何和尺寸族，记录单元数、畸变、二次节点、物理组保留率、求解收敛与结果偏差。

VTK 与 ParaView

VTK 提交 d2d1933f 修正 vtkHDFReader::CanReadFile 对文件名路径使用内存流、从而分配近似整个文件大小缓冲区的问题；对自动扫描大量 HDF 结果文件尤其重要。提交 4a5b8d83 则让数据对象比较在数组分量数或 tuple 数不一致时明确失败，避免回归测试漏报形状不一致。

ParaView 合并主题 6bce14e5 修复 Python 中 vtkSMProxy CaptureWindow 的内存泄漏。建议用同一状态文件循环截图 500 次，记录每 50 次的 RSS、输出尺寸与像素哈希；只有内存曲线趋稳且图像一致，才适合进入夜间批处理。

CalculiX 与 Abaqus-compatible 流程

求解器本周无重要发布。CalculiX 官方稳定版本仍为 2.23。值得关注的是 CADEngBench 把 CalculiX 作为匹配 FEA 评价器：只有候选与参考都能通过同一网格、材料和边界条件求解，才比较位移、应力和柔度。这一“先检查可达性，再比较响应”的两阶段逻辑适合 Abaqus-compatible 自动化，可将语法/集合/单元兼容失败与真实物理偏差分开统计。

Python / C++ / pybind11 / ABI

pybind11 PR #6143 修复 3.1.0 中“类型可复制、但显式删除移动构造函数”时返回值绑定无法编译的回归；PR #6145 使用 __has_include 防护 cxxabi.h，修复 clang-cl 等定义了 __GNUG__ 却没有该头文件的工具链。两者是已合并开发修复，不是新稳定版。

对 FreeCAD 插件应在 Windows 建立 MSVC、clang-cl 两条编译线，并加入“删除移动构造、允许复制”的返回类型夹具；运行时还需测试 Python 小版本、Debug/Release CRT、异常跨边界和 FreeCAD 内嵌解释器加载。通过编译不等于 ABI 安全。
