执行摘要

本周的主线是把 FreeCAD 26.3 RC1 放入隔离回归，而不是立即替换生产环境。该候选版于 10 月 8 日发布，官方明确仍有阻断问题。与此同时，Assembly 齿轮/皮带关节出现待确认崩溃报告；Gmsh 开发分支修正周期曲面高阶节点对应；VTK 的数组与 HDF 读取修复为后处理一致性提供了针对性测试入口。它们都比“全面升级”更适合作为可复算的验证任务。

  • FreeCAD 26.3 RC1 属预发布；需与 1.1 建立同一组装配、STEP、网格和求解基线。
  • 周期高阶网格与结果数组是本周最值得加入自动化门禁的两处数据链路。
  • IGA 与 AI/CAD 检索未发现足以替代现有生产流程的新证据；保留独立研究验证，不把旧论文写作本周进展。

本周最优先的 3 项行动

  1. 隔离跑 FreeCAD 26.3 RC1。固定同一装配文件与脚本，在 1.1 和 RC1 上比较关节位置、求解状态、保存重开后的位姿，以及错误日志；特别覆盖齿轮/皮带关节的直边选择。
  2. 复算 Gmsh 周期高阶节点。使用官方新加的三向周期立方体基准，检查周期变换前后的节点配对、单元 Jacobian、网格连接与物理组；与冻结版本对照。
  3. 锁定后处理数据契约。以 VTK-HDF 与 CellArray 缺损样例测试数组长度、类型、时间步、极值和异常显式失败；再由 ParaView Python 脚本批量重放。

FreeCAD Assembly 自动化与 API/插件变化

FreeCAD 26.3 RC1 于窗口内发布，官方将其定义为首个候选版并明确提示仍有开放的阻断问题。它不是生产稳定版，也不能仅凭版本号推断 Assembly API 已稳定。对动力学自动化，重要的是同一装配在两版中的运动、约束残差和保存重开一致性。

问题 #33409 报告在 Assembly 中用直边创建齿轮/皮带关节可能崩溃；目前为待确认问题信号，不等于所有平台可复现。把边类型、零件拓扑、关节参数、平台和 FreeCAD 版本写入最小复现文件，分别测试 GUI 与脚本路径；若崩溃发生在求解前，应先排查几何引用而非调节动力学求解参数。

本窗口扫描官方提交时，未核验到可称为 Assembly 公共 API 正式发布的新接口。Part 附着引用容器修复与 FEM 的 VTK 兼容方法修复可作为相邻模块回归项，但不应包装成 Assembly 求解器更新。

IGA / CAD–分析一体化

本周无重要可确认发布。对 G+Smo、GeoPDEs、PetIGA、tIGAr、igatools 的项目仓库、正式版本与论文检索，没有找到在固定窗口内同时具有原始证据、可复算量化指标和足够工作流影响的新成果。此结论只描述本次检索边界，不否定长期研究进展；NURBS/B-spline、T-spline、THB-spline、LR-spline、IBRA 与 trimmed/immersed IGA 的旧成果不计入本周新闻。

FreeCAD/OCCT 到 IGA 的基线实验仍应逐面记录控制点、节点矢量、权重、次数、参数域、内外修剪环和 pcurve，再检验跨面连续性及边界条件映射。对切割单元记录积分失败率、条件数、自由度、组装/求解时间和内存。用同一修剪壳分别进行 IGA 与“STEP—Gmsh 二次网格—CalculiX”静力及前六阶模态计算，比较几何误差、位移和频率；没有这些量化结果，不能声称 CAD–分析一体化更优。

AI × CAD/CAE

本周无达到纳入门槛的新工作。检索覆盖 Text-to-CAD、programmatic/agentic CAD、CAD copilot、装配约束与验证、几何修复、自动参数化、拓扑优化、AI 网格、载荷/边界识别、参数标定、solver acceleration、ROM、surrogate、PINN、neural operator、digital twin 与后处理异常检测。窗口外的 CADForge 等预印本不能冒充本周论文。

对 FreeCAD 工作流，保留四层可复算门禁：脚本可执行；B-Rep 有效且 STEP 可重导入；参数扰动后装配关节仍可求解；固定 Gmsh/CalculiX 输入下的位移、反力、应力分位数和模态误差达标。任何代理若只给出渲染相似度，未给出代码、数据、装配约束状态及失败日志，就只能作为候选生成器。风险是视觉正确掩盖几何与物理错误；应以盲测、固定种子和失败样例集验证。

CATIA 与 Rhino / STEP / 3DM 互操作

rhino3dm 官方仓库在窗口内合并 9.0 同步提交。这属于开发分支同步，不等于 3DM、STEP 或 CATIA 之间的几何语义已全面保真。测试件应包含有理 NURBS、内孔修剪、单位、图层与对象属性；比较 Python 与 JavaScript 往返后的控制点/节点/权重、修剪环方向、包围盒和文件重读结果。本窗口未核验到 CATIA/STEP 官方互操作规范的重要新发布。

Gmsh 与 meshio

Gmsh 开发分支的 周期曲面节点匹配修复涉及 transfinite、extruded 曲面及其高阶节点；随后 细分三角形到四边形的中心节点映射和三向周期立方体基准提供了可直接复跑的实验入口。它们是开发提交，不是稳定版发布，也没有可引用的独立性能倍率。

试件固定条件应记录
周期立方体相同尺寸场、阶次、线程数配对节点缺失数、周期残差、Jacobian 最小值
修剪曲面相同 STEP、物理组节点/单元数、边界误差、失败率
MSH4 往返冻结 meshio 版本单元类型、物理组、节点坐标差

meshio 官方仓库在窗口内无提交；维持冻结版本并以 MSH4 高阶/分区样例做往返，避免把 Gmsh 改动误判为 meshio 更新。

VTK 与 ParaView

VTK 在窗口内合并 Python 数组与 NumPy 一致性、VTK-HDF 图像缓存及HDF 读取溢出修复相关主题。ParaView 的 Python UpdatePipeline 增量更新也进入开发分支。应把这些变更视为数据正确性和执行路径信号，非稳定版承诺。

验证时固定一个多时间步结构动力学结果：对每步比较数组数量、dtype、shape、NaN 数、极值和单元/节点 ID；故意注入超长或缺损 HDF 数据，要求显式报错而非静默截断。ParaView Python 重放前后比较更新次数、结果哈希和运行时间，不用单一渲染截图判断数据等价。

CalculiX 与 Abaqus-compatible 流程

本周未核验到重要正式发布。维持输入兼容与物理等价两层测试：第一层检查单元、材料、集合、载荷、边界、接触与输出关键字可解析；第二层对解析解或冻结 Abaqus-compatible 基线比较反力平衡、位移、应力分位数与前六阶模态。网格或后处理变更都不能替代求解器等价性证据。

Python / C++ / pybind11 / ABI

pybind11 窗口内合并 keep_alive 失败重载处理修复：未匹配的重载或失败的返回转换不应错误激活生命周期关系。它是开发提交，不等于新正式版本。对 FreeCAD 插件应在 MSVC/clang-cl、Release/Debug 和目标 Python 版本组合下测试重载失败、异常传播、对象销毁、重复加载和解释器关闭；通过编译不代表 ABI 或生命周期安全。
