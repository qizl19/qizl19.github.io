面向 FreeCAD 动力学自动化工作流

报告日期：2026-07-27　检索窗口：2026-07-20 09:00 至 2026-07-27 09:00（Asia/Shanghai）　联网核验截止：2026-07-27 09:00

执行摘要

本周最直接影响 FreeCAD 动力学自动化的变化来自两项已合并开发改动。其一，FreeCAD PR #29904 将编译资源改为 zstd 压缩并消除 Assembly Python 资源的重复装载：示例构建资源由 71.0 MiB 降至 9.63 MiB，约缩小 7.4 倍，同时多个 Python 资源模块的导入测试显著加快。其二，FEM PR #31055 为 CalculiX Contact 和 Tie 增加主从面反转选项，解决“几何选择顺序与求解器主从语义不一致”时只能重选对象的问题。两者均已合并，但都不是稳定版发布，不能据此跳过隔离回归。

AI × CAD/CAE 侧出现三项值得验证、但不能直接替代求解器的信号。一个面向非线性变分不等式的 POD + 神经非线性流形 + 稀疏求积框架，在 3D Coulomb 摩擦接触测试中报告 1790 倍在线加速和 1.66% 平均能量误差；与此同时，全界面约束审计仍显示约 3.43% 负法向力指标与 6.48% 摩擦界指标，这恰好说明“场误差低”不等于“接触约束可靠”。无标签有限体积残差 GNN 在两个稳态热流体基准上取得 2.3%–2.8% 全场 nRMSE，并公开代码与数据，但训练用了 8 张 RTX 4090、约 200 小时。SHA-PF 则让 LLM 搜索仿真优化问题的目标/约束表述，在五个天线 HFSS 基准上均找到满足要求的设计；它优化的是问题表述，不是自动生成 CAD，也没有消除高保真仿真的复算责任。

后处理与集成链同样有可操作信号：VTK 修复 SurfaceNets 奇偶尺寸崩溃和三角退化时单元颜色错位；ParaView 增加 Fides Catalyst 提取器、Conduit 通道，并修正时间缓存和科学计数法文件序列解析；pybind11 开发线修正切片删除与 CMake/Python 解释器发现。Gmsh、meshio、rhino3dm、OCCT 和 CalculiX 稳定发布在本窗口内没有可核验的新版本。建议本周把精力放在资源启动、主从面语义、接触全约束审计三类可复算回归，而不是追逐版本号。

本周最优先的 3 项行动

  1. 建立 FreeCAD 资源打包与启动基线：在隔离构建中比较 PR #29904 前后安装包、resources.rcc、冷启动、二次启动和 Assembly/FEM 工作台首次激活时间；用同一插件集合重复 20 次，记录中位数、P95、缺图标和重复资源警告。若 Qt < 5.13、第三方资源或打包脚本失败，则保持现有生产构建。
  2. 冻结 Contact/Tie 主从面往返测试：构造一对刚度比明显、网格密度不同的接触体，分别用默认顺序与反转开关生成 .inp；核对 *CONTACT PAIR/*TIE 引用、面集合、结果穿透、接触压力、反力平衡和保存重开后的属性。不要只检查树中出现复选框。
  3. 以“全约束审计”验证 AI 降阶：从一个已有 CalculiX 摩擦接触模型抽取 30–50 个参数点，比较 HDM、线性 POD 和神经/超降阶候选的位移能量、穿透、负法向力、摩擦锥越界、求解时间和域外报警。只有场误差与约束误差同时达标，代理才允许进入交互预览层；最终签署仍由真实求解器完成。

FreeCAD Assembly 自动化与 API/插件变化

资源压缩与 Assembly 重复资源消除

【已合并开发变更】FreeCAD PR #29904：Reduce rc file size 于 7 月 20 日合并。变更同时覆盖 C++ rcc 和 Python 资源生成：采用 zstd 19 级压缩、修正 CMake 资源依赖，并移除重复生成的 Python Assembly_rc，因为 Assembly 的 C++ 资源会在 import AssemblyGui 之前装载。

PR 给出的构建测量中，资源由 71.0 MiB 降至 9.63 MiB，减少 61.37 MiB，约为原体积的 13.6%；导入测试中 Arch_rc、Draft_rc、Help_rc、Tux_rc 分别报告约 533、151、8.5、5.8 倍加速。这里的数字是资源模块导入微基准，不能等同于整个 FreeCAD 冷启动加速。

工作流影响：安装包和内存压力下降，Assembly 资源不再双份装载，适合插件众多的长期工作台。兼容边界：zstd 压缩要求 Qt 5.13 以上；第三方工作台仍可能自行生成独立 _rc.py，不能从核心变更推断所有插件自动受益。风险/置信度：高代码证据置信度、中等打包兼容风险。验证：比较资源文件哈希/体积、工作台图标完整性、导入异常、冷/热启动 P50/P95，并在 Windows 打包环境单独验证。

Contact 与 Tie 主从面可反转

【已合并开发变更】FreeCAD FEM PR #31055 于 7 月 20 日合并，为 Contact 和 Tie 约束加入“Reverse master/slave”布尔列表，并让 Tie 使用分离的主面/从面选择器。写入端实际修改了 CalculiX 的 write_constraint_contact.py 与 write_constraint_tie.py，因此这不是纯界面按钮。

迁移价值：自动生成接触对时，可以保留几何选择和对象身份，再显式调整求解器主从语义；这对刚柔接触、粗细网格接触和批处理修复更稳。局限：当前 PropertyBoolList 是以后放宽“一主一从”限制的准备，不代表已经支持任意多主从配对；主从选择也不会自动替代接触参数、法向方向和网格质量判断。风险/置信度：高实现置信度、中等工程误用风险。验证：必须检查保存重开、属性长度、对象删除/重连、.inp 集合顺序、穿透和反力平衡。

对动力学自动化的真正含义

本周没有证据表明 FreeCAD Assembly 关节 API、求解器语义或时间积分接口发生稳定发布级变化。资源和 FEM 接触改动改善的是启动/打包与前处理语义。因此建议把它们纳入构建与求解输入的回归矩阵，而不要改写现有 TDY/Assembly 结果协议或历史文件结构。

AI × CAD/CAE

神经非线性流形 + 超降阶：3D 摩擦接触的速度与约束账本

【预印本】A Hyper-Reduced Neural Network-Augmented Semi-smooth Newton Method 将原始/对偶变量的 POD、前馈网络校正、半光滑 Newton 和基于非负最小二乘的稀疏求积组合，用于二维障碍问题与三维 Coulomb 摩擦接触。三维接触数据包含 2000 个训练参数点、200 个验证点和 200 个独立测试点；其中选 1500 个高维快照构造 POD。线性 ROM 保留 150 个主坐标，神经模型把在线主变量与切向乘子坐标各压到 25；超降阶接触面由 423 个降到 285 个。

论文报告：标准 ROM 的平均能量误差 1.08%、加速 54.8 倍；加上弹性预测器代理后为 1.26%、399 倍；HR-ROM 为 1.43%、798 倍；NN-ROM 为 1.65%、979 倍；最终 NN-HR-ROM 为 1.66%、1790 倍。关键的完整约束审计并不完美：平均残余穿透约 0.28%，神经模型的负法向力与摩擦界指标约 3.42% 和 6.49%。

开放性：arXiv 提供论文与 TeX 源码，但页面和正文未给出代码仓库，复现成本高。迁移价值：方法可映射到 FreeCAD/CalculiX 的参数化接触结果预览、优化内环和数字孪生快速响应。失效模式：低能量误差掩盖局部接触力越界；训练域外摩擦系数、接触拓扑改变、开闭状态切换和新网格都可能破坏低维流形。风险/置信度：中高研究置信度、高直接部署风险。Go 条件：自有模型必须同时满足场误差、接触约束、反力/能量平衡和域外拒绝门限；否则只作候选排序。

无标签有限体积残差 GNN：省去 CFD 标签不等于省去算力

【预印本 + 代码公开】Label-Free Finite-Volume-Residual Training of Attention GNNs 在原始非结构网格上，以连续性、动量、能量和压力基准的离散 FVM 残差训练注意力图网络，不需要高保真解作为标签。两个稳态基准的全场 nRMSE 为 2.3%–2.8%；两个参数化瞬态案例中，残差训练模型优于相同骨干的监督基线，并避免生成训练标签。代码与数据公开。

成本边界必须一起报告：数据中心案例使用约 14 万网格单元、300 条 CFD 轨迹的边界条件组合；训练在 8 张 RTX 4090 上进行 2400 个 epoch。论文附录给出的圆柱尾迹训练约 203.71 小时、数据中心约 200.38 小时，比监督训练约多 17%；总管线成本之所以更低，是因为省去了高保真标签生成，而不是网络训练廉价。

迁移价值：可用于热-流体数字孪生、参数扫掠和网格图代理，且损失直接对应守恒离散。局限：FVM 残差的条件数会随网格细化恶化；边界条件、湍流闭合、网格拓扑和瞬态稳定性仍决定泛化。风险/置信度：中等研究风险、低近期工作站可迁移性。验证：先用 20 个边界条件、两档网格做小样，比较守恒残差、全场误差、积分热量/流量、长时滚动漂移和训练能耗；若只看像素/场图相似则 No-Go。

SHA-PF：LLM 优化“仿真问题表述”，不是 Text-to-CAD

【预印本】Search Hardness-Aware LLM-Based Problem Formulation 让 LLM 生成、修复并进化目标函数和约束，通过初始样本中“稀有但有进展潜力”的满足状态评价候选表述。实验统一使用 GPT-5-mini、100 个初始样本和 SCBO；HBV 校准预算 250 次，五个天线任务各 300 次 HFSS 仿真。

在五个天线任务上，SHA-PF + SCBO 找到首个合格设计分别需要 66、85、63、10、90 次额外 HFSS 仿真；四个专家/直接 LLM 基线中的大多数在预算内失败，唯一成功的 LLM-A 在 HAE/CSL 分别需要 71/36 次。HSL、HSE、WHG 上，论文报告 SHA-PF 比失败基线少 110–137 次仿真，并节省 1.5–11.2 小时。

开放性：论文 HTML 提供完整表述代码和提示模板，但未给出独立可运行仓库或 HFSS 模型包。迁移价值：适合把自然语言设计要求转成可审计的目标/约束候选，再由 FreeCAD/CAE 流程求解。局限：基准只有一个水文校准和五个天线问题，表述搜索本身依赖 LLM；成功不证明 CAD 几何、载荷、边界条件或单位正确。风险/置信度：中等方法置信度、高自动执行风险。建议实验：用同一 30 个已验证设计任务比较人工、直接 LLM、SHA 类表述，在同一优化器/预算下统计可执行率、单位错误、约束遗漏、达到门限的真实求解次数和人工修复次数。

可微 GPU 求解器：对 CAE 架构有启发，但领域迁移必须保守

【预印本】yancc 是 JAX 实现的 GPU 可微新经典输运求解器。论文报告与 MONKES、SFINCS 在多种碰撞率、几何和多组分配置下结果相差 1% 以内，相对 SFINCS 每次扫描约快一个数量级、内存约少一个数量级，并能直接做梯度优化与伴随敏感度。

迁移价值：“离散算子 + 预条件 Krylov + 自动微分 + 梯度优化”可作为结构/热/流体求解器加速的架构参照。边界：这是等离子体漂移动力学，不是结构、接触或 FreeCAD 求解器；arXiv 页面未给出代码仓库，且速度来自特定 GPU/扫描设置。故本期只列为可微求解器工程信号，不纳入近期集成计划。

CATIA 与 Rhino / STEP / 3DM 互操作

【本周无重要变化】窗口化检查中，McNeel rhino3dm 与 Open CASCADE Technology 官方仓库没有新提交或 release；OCCT 最新稳定发布仍是 2026 年 5 月的 8.0.0。也未找到 Dassault Systèmes 官方材料中可复现、可量化的 CATIA–STEP/3DM 新变化。

建议：不调整现有互操作基线。继续用固定 CATIA/STEP/3DM 样件做往返：单位、产品层级、实例变换、颜色/属性、NURBS/B-Rep 有效性、缝合容差、体积/质心/惯量和文件哈希。对商业产品声明，若没有版本号、导出设置、样件与误差数据，只进入待核验池。

Gmsh 与 meshio

【本周无重要变化】Gmsh 官方站仍以 4.15.2 文档和下载为稳定基线；canonical GitLab 受 Anubis 反机器人挑战保护，窗口内无法直接读取 commit API，但官方站的发布与源代码索引没有显示本周新稳定版本。meshio 官方提交历史的主线最新批次仍在 2024 年，窗口内无发布信号。

工程判断：本周没有网格算法或格式桥接升级理由。保持 Gmsh 4.15.2 + 当前 meshio 基线，继续对 .msh 2.2/4.1、二阶单元、physical group、分区、节点/单元 ID、VTK/XDMF 字段和 Abaqus 集合做黄金样例往返。只有新版本解决当前缺陷并通过相同哈希/语义测试时才升级。

VTK 与 ParaView

VTK：网格拓扑、颜色数组与交互裁剪

【开发线修复】VTK 本周值得关注的提交包括：vtkSurfaceNets3D 奇偶尺寸崩溃修复；保留退化三角形以维持单元颜色数组对齐；以及动画时自动调整相机裁剪范围。另有 Center of Rotation 与 WebAssembly/JSPI 相关开发提交。

CAE 影响：SurfaceNets 修复关系到体数据等值面；退化三角形策略避免“删除几何后颜色索引错位”，但会保留零面积单元，需要下游统计明确是否计入；相机自动裁剪改善长行程动画，却可能改变帧间近/远裁剪和深度精度。验证：用奇/偶维体数据、含退化三角形和 cell color 的网格、长行程装配动画，比较 cell 数、数组映射、近远裁剪、截图哈希和 Z-fighting。

ParaView：Fides/Catalyst 与时间序列可靠性

【开发线功能与修复】ParaView 新增 Fides Catalyst pipeline extractor、Fides Conduit channel和配套构建/测试；文件序列解析支持索引与科学计数法，缓存命中时不再沿用旧的 DATA_TIME_STEP。开发线也在汇总 6.2 release notes，并跟进 VTK 9.7 API 变化。

工作流影响：原位计算数据可通过 Fides/Conduit 更直接进入 Catalyst；时间步修复有利于长序列后处理和结果证据。局限：均为开发线，Fides 数据模型、Conduit 通道和 VTK 9.7 依赖会带来编译与语义风险。验证：用含科学计数法编号、缓存回放、乱序请求和多字段的固定序列，比较时间值、步数、数组范围、截面/积分结果和退出稳定性。

CalculiX 与 Abaqus-compatible 流程

【上游前处理开发变化】本窗口内最实用的 CalculiX-compatible 信号就是 FreeCAD PR #31055：Contact/Tie 的主从面反转会改变生成的输入文件引用顺序。CalculiX 稳定站点没有窗口内新 release，因此不能把 FreeCAD 写入端改动描述成 CalculiX 求解器升级。

验证最小集：一对刚柔接触、一对粗细网格 Tie、一个多载荷步开闭接触；分别记录输入关键字、面集合、穿透、接触压力、反力、能量和 FRD 场。Abaqus-compatible 只表示部分输入语法兼容，不意味着接触算法、默认值、输出变量和收敛行为等同。若反转前后物理结果差异无法由网格/主从选择解释，则回退并保留生成的 .inp 证据。

Python / C++ / pybind11 / ABI

【开发兼容信号】pybind11 本周主线包含四类变化：修复 stl_bind 负步长切片删除并增加连续区间快速擦除；CI 增加 Python 3.15；CMake 发现改用预期 Python 解释器；并清除残留的 PYTHON_MODULE_DEBUG_POSTFIX、修正 USE_PYTHON_INCLUDE_DIR。这些是开发提交，不是新的稳定 ABI 保证。

对 FreeCAD 插件的影响：绑定容器若暴露类似 Python list 的切片删除，修复值得纳入测试；CMake/Python 发现变化可减少“编译时 Python 与运行时 Python 不同”的隐患。建议：在 Windows/MSVC 与目标 FreeCAD Python 上固定编译矩阵，至少测试 import、对象创建/销毁、异常跨界、字符串/Unicode、NumPy buffer、容器切片、debug/release 后缀和保存重开。记录 Python minor、MSVC runtime、Qt、OCCT、VTK、pybind11 与编译选项；能导入不代表 ABI 和对象寿命安全。
