面向 FreeCAD 动力学自动化工作流

报告日期：2026-08-03　检索窗口：2026-07-27 09:00 至 2026-08-03 09:00（Asia/Shanghai）　联网核验截止：2026-08-03 09:00

执行摘要

本周最值得进入 FreeCAD 动力学自动化回归线的信号，不是 Assembly 关节 API 的大改，而是可提取结果、二维模型口径和几何内核稳健性。FreeCAD 发布了 weekly-2026.07.29 开发周构建；随后合并的 FEM PR #31667 将 Elmer 特征频率与屈曲因子保存成可读取的标量及元数据，PR #31610 修正二维机械方程的自由度与单位厚度口径。两项属于已合并开发变更，后者和前者是否进入某一周构建仍应按提交边界核对。

OCCT 8.0.1 是窗口内正式发布：保持 8.0.0.p1 的 C++17/API/ABI 基线，集中修复 B-spline 周期参数、形状修复、STEP 输出、周期缝网格和并发圆角。公开基准中，含 2000 个孔的面校验由 9.21 秒降至 1.11 秒，曲面偏差快速路径使相关布尔工作负载改善约 17%–20%。这比“格式兼容”更直接影响 FreeCAD 的 STEP/修剪曲面/网格前处理可靠性。

IGA / CAD–分析一体化在 G+Smo、PetIGA、tIGAr、igatools 等公开主线中未发现窗口内 release 或提交，也未检出可同时满足时间窗、量化结果与开放性的强新论文，因此本期明确记为“本周无重要变化”，不以旧论文填充新闻。AI × CAD/CAE 同样没有发现比上期更强、且能在本周窗口内完成量化与复现核验的新成果；本期把重点转为覆盖矩阵和验证门禁。工程上应优先完成一个 OCCT/STEP NURBS 保真提取—IGA—Gmsh/CalculiX 对照样例，而不是将无代码预印本直接接入生产。

本周最优先的 3 项行动

  1. 建立 Elmer 特征值自动收集器：在隔离 FreeCAD 开发构建中复现 FEM PR #31667，用悬臂梁与屈曲柱各一个模型读取保存的频率/屈曲因子、字段名、单位和求解元数据；与 Elmer 原始输出及 CalculiX 结果逐项对账，保存重开后再次读取。
  2. 冻结二维力学单位与接触回归：按 PR #31610 的“平面模型单位厚度、载荷量按单位长度”口径，分别验证平面应力、平面应变、轴对称和 Edge 接触；把总反力、能量、位移与解析/三维薄片基线纳入门禁。
  3. 做一条 OCCT→IGA→FEM 保真链：从同一 STEP/OCCT 面提取次数、控制点、节点矢量、权重、参数范围、修剪环和邻接连续性；对未修剪 NURBS 与带孔修剪面分别做 IGA 和 Gmsh/CalculiX 网格加密，比较几何偏差、自由度、频率/位移、条件数、积分时间和失败单元。

FreeCAD Assembly 自动化与 API/插件变化

开发周构建与 Assembly 边界

【开发预发布】weekly-2026.07.29 于 7 月 29 日发布，官方明确标注为用于测试修复、回归和新功能的 bleeding-edge 构建，不应用于生产。本窗口检索到的 Assembly 专属已合并变更中，没有可证明关节语义、求解接口或持久化格式发生重大调整的项目。因此“有周构建”不等于 Assembly API 已稳定升级。

Elmer 特征频率与屈曲因子进入可编程结果链

【已合并开发变更】FreeCAD FEM PR #31667 于 8 月 1 日合并，使用 Elmer SaveScalars 保存 elasticity equation 的 eigenfrequencies 与 buckling factors，并把数值与元数据汇入输出文本对象；PR 同时更新了弯曲屈曲示例。变更规模为 3 个提交、7 个文件，核心价值是让批处理不再依赖人工抄读日志。

方法与开放性：代码、示例和测试均公开。量化边界：PR 没有给出求解误差或大模型性能基准，不能声称精度/速度提升。工作流影响：可把模态频率、屈曲因子、求解设置和模型哈希写入同一结果快照，适合 FreeCAD→Elmer/CalculiX 双求解器审计。失效模式：输出字段顺序、单位、重根/近重根、失败求解和保存重开可能产生空值或错配。置信度：实现证据高，工程验证中等。

二维力学模型不再假装是三维单位口径

【已合并开发变更】FreeCAD FEM PR #31610 于 7 月 28 日合并：二维 mechanical equation 的变量自由度设为 2；平面模型按单位厚度解释，相关量应按单位长度而非单位面积输入；轴对称案例维持其预期口径，并更新了轴对称轴示例。

风险：旧自动化如果把三维面载荷直接复用于二维平面模型，修复后可能暴露数量级错误。验证：用解析悬臂梁、轴对称厚壁筒和等效三维薄片做三组复算；报告总载荷、单位换算、反力平衡和网格收敛，不只看云图相似。

Edge 接触提示与嵌入文件 I/O

PR #31516 仅把 FEM Contact 任务面板提示从 Faces 扩展到 Edges，以说明二维模型可选边；这是 UI/可发现性修复，不是新接触算法。PR #30478 把嵌入文件的逐字符读写改为固定块缓冲并新增字节完整性回归测试；作者观察到打开模型改善，但没有公开秒级基准，因此只能记为性能方向信号。

IGA / CAD–分析一体化

本周结论与检索边界

【本周无重要变化】检索覆盖 IGA、IBRA、trimmed/immersed IGA，NURBS、B-spline、T-spline、THB-spline、LR-spline，以及结构动力学、壳/实体、接触、断裂、多物理、拓扑优化、并行/GPU、预条件、ROM 与神经算子组合。公开仓库窗口检查显示 G+Smo、PetIGA、tIGAr 与 igatools 在 2026-07-27 01:00Z 至 2026-08-03 01:00Z 没有公开提交；未找到可核验的新正式版本。GeoPDEs 的公开发布渠道也未显示窗口内新版本。

论文检索只把提交/发布位于本窗口、原文可访问且给出可核查 benchmark 的成果算作新闻。未检出同时满足这些条件的强新结果，故不引用 2016–2025 年的经典 trimmed IGA、扩展 B-spline 或自适应论文冒充本周进展。商业产品若只有功能声明而无模型、自由度、误差、时间与失败案例，本期不升级其证据等级。

OCCT 8.0.1 是几何入口的现实变化

【正式发布】OCCT 8.0.1 保持 8.0.0.p1 的 C++17 与 API/ABI 基线，修复周期 B-spline 参数归一化导致的布尔挂起、缺失 pcurve/非流形边界的形状修复崩溃、周期缝网格约束、STEP 长字符串与 writer healing 参数。它并未提供 IGA 求解器，但直接影响从 FreeCAD/STEP 获取可分析 NURBS 与修剪拓扑的可靠性。

公开量化包括：2000 个孔的面校验从 9.21 秒降到 1.11 秒，约 8 倍；曲线在曲面上的偏差快速路径使相关布尔工作负载改善约 17%–20%，并保持结果形状和测试结果不变。局限：这些是 OCCT 维护基准，不等同于 IGA 组装/求解加速；对极小 cut cell、近退化 trimming loop、跨周期缝参数映射和多 patch 连续性仍需专门测试。

AI × CAD/CAE

本周筛选结论：没有通过全部门禁的新条目

【本周无高置信度新结果】本期检索了 Text-to-CAD、programmatic CAD、CAD copilot、agentic CAD、装配约束、几何理解/修复、自动参数化、拓扑优化、AI 网格、边界条件/载荷识别、参数标定、solver acceleration、ROM、surrogate、PINN、neural operator、digital twin、后处理与异常检测。只把窗口内新发布、含明确数据/benchmark、量化结果、开放性信息并能设计 FreeCAD 迁移实验的成果列为重点；未发现优于上期接触 ROM、无标签 FVM-GNN 等证据质量的新条目。

这不表示领域停滞，而是新闻门槛生效：只有产品演示、未公开数据、无几何有效性指标、只报告平均场误差或没有基线的结果，均不进入“本周进展”。旧工作可作为验证方法背景，但不计为本周新闻。

CATIA 与 Rhino / STEP / 3DM 互操作

【正式发布】OCCT 8.0.1 的 STEP writer 会在 transfer 前恢复缺失的 shape-processing 参数，并安全分割超过 72 字符输出缓冲的 STEP 字符串；形状修复覆盖缺失 pcurve、空线序列、非流形边界和周期圆锥面。这些修复适合用 CATIA→STEP→FreeCAD/OCCT 往返样件验证，不能自动推断 CATIA 原生特征树可保留。

【开发中变更】rhino3dm 合并 8.32.1 分支，并在 JavaScript 侧调整 3DM point cloud 为 three.js buffers。官方 GitHub releases 没有对应完整发布说明，因此本期按开发/发布流程信号处理，不声称 3DM 几何互操作得到量化改善。

验证：固定 CATIA/STEP/3DM 样件，核对单位、产品层级、实例变换、颜色/属性、长名称/Unicode、NURBS 权重与 knots、修剪环、缝合容差、点云数量/颜色、体积/质心/惯量。CATIA 原生参数、Rhino 用户数据和 STEP AP242 属性必须分别列账，不用“文件能打开”代替语义保真。

Gmsh 与 meshio

【本周无重要变化】Gmsh 官方稳定页与 meshio 官方仓库未显示窗口内 release；meshio 主线也没有窗口内公开提交。保持当前版本，继续用 .msh 2.2/4.1、二阶单元、physical groups、分区、节点/单元 ID、VTK/XDMF 字段和 Abaqus 集合做黄金样例往返。

IGA 对照新增两个几何：未修剪 NURBS 方板与带孔修剪面。Gmsh/FEM 路线记录几何逼近误差、网格自由度与结果收敛；IGA 路线记录控制网、cut-cell 积分和条件数。两边必须使用同一材料、载荷、约束与质量归一化，避免把几何表示差异误写成求解器优劣。

VTK 与 ParaView

【开发线功能】VTK 在窗口内为 vtkOCCTPDCReader 合并二进制 BREP、子面/子边着色、OCCT 8 支持与颜色处理改进：Binary BREP、sub-face/sub-edge color、OCCT 8 support。还新增 1D/2D extent 的 VTKHDF 写入与读取修复，并修正 String/Variant/BitArray 内存分配。

工作流影响：FreeCAD/OCCT 形状可更完整地进入 VTK 后处理，颜色可作为面/边集合身份的辅助证据。局限：颜色不是稳定拓扑 ID；reader 三角化结果也不是 NURBS/IGA 几何。验证：同一 BREP/STEP 比较形状数、子面/边颜色数组、包围盒、三角形数量、内存和二进制/文本 BREP 一致性。

【开发线修复】ParaView 修复了上下文视图交互中多余 EndInteractionEvent 导致的 undo set 错误，以及改变代理时 property link 崩溃，并同步轴对齐反射缓存修复。暂无窗口内稳定版本发布；升级前仍需用时间序列、缓存、反射、PythonCalculator 和远程渲染样例验收。

CalculiX 与 Abaqus-compatible 流程

【本周无求解器正式发布】CalculiX 官方站未显示窗口内新稳定 release。本周动作应围绕 FreeCAD 输入/结果端：二维 Edge 接触、单位厚度载荷、模态频率/屈曲因子字段，以及 OCCT 修复后面集合是否变化。

Abaqus-compatible 只描述部分输入关键字或文件结构兼容，不代表接触算法、默认积分、单元公式、收敛准则与输出变量等价。对照实验必须保存两边实际输入文件，比较自由度、质量、前 10 阶频率、MAC、反力/能量、接触穿透与警告；若集合映射改变，先修复前处理，不用结果“看起来接近”放行。

Python / C++ / pybind11 / ABI

【开发线破坏性变化】pybind11 PR #6110 于 8 月 1 日合并，主线要求 Python 3.9+、MSVC 2019+，放弃 Python 3.8 与 MSVC 2017。这不是当前稳定版 3.0.4 的即时要求，但对下一轮依赖升级是明确门禁。

【开发线缺陷修复】PR #6096 修复从 generator 构造 std::string_view 容器时的 use-after-free，只为瞬态来源添加生命周期支撑，并以 ASAN 和新增测试验证。PR #6094 让 CMake 4.1/CMP0190 下显式的交叉编译设置得到尊重。

工作流影响与风险：FreeCAD 插件若绑定 string_view、generator、NumPy buffer 或跨线程对象，导入成功并不能证明生命周期安全。建议固定 Python minor、MSVC runtime、Qt、OCCT、VTK 与 pybind11 版本矩阵；新增 generator/string_view 压力测试、异常跨界、对象销毁、debug/release 与保存重开测试。生产环境保持当前已验证组合，待上游正式发布并完成 ABI 回归后再升级。
