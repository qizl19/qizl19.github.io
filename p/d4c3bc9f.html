CAD/CAE 生态周报｜2026-11-16

发表于2026-11-16|更新于2026-11-16|CAD/CAE 生态周报
|字数总计:11.2k|阅读时长:26分钟|阅读量:

定位：面向 FreeCAD 动力学自动化工作流。

执行摘要

本周的主线是把“几何、装配语义、边界条件与数值证书”一起保存，而不是只保存模型或云图。FreeCAD weekly-2026.11.11 是开发预发布，包含跨文档 joint snapping 的临时几何修复；随后主线又合并嵌套 BOM 数量分组和镜像 Link 崩溃修复，但后者晚于该 weekly 的 tag。已确认问题 #34381 表明在 Joint 编辑期间双击另一对象会永久清空原引用，保存重开后可触发 NoneType 错误，自动化必须把 Task Panel 重入纳入状态机测试。

IGA/CAD–分析一体化本周有三类可量化证据：几何非线性 IGA 梁到流体界面的功共轭映射在强弯扭下把虚功差压到约 10−11–10−10；NURBS 曲壁有限体积在 41,344 单元的 Couette 测试中把三次重构速度误差由多边形几何的 4.626×10−5 降至 3.493×10−7；THB/HB 样条局部粗化在 24,432 DOF 的移动前沿测试上给出可预判的 L∞ 误差界。AI 侧，能量范数训练把 3D transformer 的中位能量误差降低 7.5 倍、von Mises 误差降低 6.1 倍；Ms-LegONet 在 3D 多查询链上报告 30–900 倍加速和 10−4 相对误差。二者都比只看位移 MSE 或单次推理时间更贴近 CAE 验收。

  • 建立 FreeCAD Assembly 状态回归：跨文档 edge/face snapping、嵌套 BOM、镜像 Link、Joint Task Panel 重入、保存重开和非单位 Placement 子装配标记。
  • 建立 OCCT/STEP 精确几何到 IGA/传统 FEM 的双轨真值件：控制点、节点矢量、权重、trim/pcurve、连续性、边界条件、功/能量与动力学 MAC 同时比对。
  • 把 AI 候选输出改为“意图清单 + 可重算模型/网格 + 求解输入 + 能量/残差/守恒证书 + OOD 拒绝”，禁止只凭云图或 LLM 评审放行。

本周最优先的 3 项行动

  1. 先封装配交互状态。在 weekly-2026.11.11 与当前主线各跑同一矩阵：外部文档 Link 的 vertex/edge/face/cylinder snapping；两级 BOM 中重复紧固件和镜像 Link；编辑 Joint 时双击 Body/另一 Joint 后分别 Cancel/OK；保存、关闭、重开并比较引用字符串、JCS、Placement、约束残差和 BOM 树。#34381 尚未修复，失败应阻断批处理。
  2. 做一组精确几何双轨验证。从 OCCT 的 BSpline surface/curve 导出 degree、poles、knots、multiplicities、weights、u/v 参数域、edge pcurve、wire orientation 与 seam；一轨进入 IGA/高阶曲壁离散，一轨经 Gmsh 二次/高阶单元到 CalculiX。比较 Hausdorff/法向误差、trim 环闭合、Jacobian、功/能量、反力、固有频率、振型 MAC、条件数、组装/求解时间与峰值内存。
  3. 把 AI 放进证书驱动的闭环。用能量范数 surrogate 先筛高应力错误；用 Ms-LegONet/PhysICL 只做候选 ROM 或场预测；用 MechFoundry/拆解 agent 生成载荷、材料或操作建议时，要求单位、支撑、载荷路径、接触、材料来源和拒绝理由可追踪，并由 CalculiX/基准解复算。

FreeCAD Assembly 自动化与 API/插件变化

weekly-2026.11.11 于 11 月 11 日发布，官方明确它是用于测试新功能和回归的 bleeding-edge 预发布，不用于生产。其 tag 指向 e140bd8，因此 11 月 13 日才合并的 BOM 修复不在该构建中。

PR #34282 修复 Assembly snapping 对跨文档外部 Link 使用持久命名映射时的 string hasher 不匹配。修复改为 Part.getShape(..., noElementMap=True) 取得临时几何索引，并新增 104 行 C++ 测试覆盖有效/无效 edge/face snapping。它解决的是 UI 选点到几何索引的可靠性，不证明拓扑命名在模型编辑后稳定；回归仍要加入加/删特征后的重新寻址。

PR #31136 在遍历每一级 BOM 时只对同级 sibling 分组，避免不同层级重复零件被错误合并；同一修复还处理了镜像 Link 路径上的不安全 cast 崩溃。它在主线合并，但没有作者给出的性能 benchmark。建议用 2–4 层子装配、共享实例、镜像/缩放 Link、循环引用拒绝和 Unicode 标签构造黄金 BOM JSON。

确认问题：

  • #34381 已确认：Joint Task Panel 打开时双击另一对象，前一 Joint 的 references 会被清空并永久保存，重开可报 'NoneType' object is not subscriptable。这是状态机/事务错误，不能靠 recompute 发现。
  • #34419 是社区问题信号：在非单位 Placement 子装配中，JCS 3D 标记偏移恰好等于子装配 Placement，报告例中约 60 mm；求解与 Placement1/2 正确，只是标记错误。报告基于 1.1.3，尚不能当作当前主线回归，但应加入视图/求解分离验收。

IGA / CAD–分析一体化

检索边界：固定窗口 2026-11-09 08:47 至 2026-11-16 08:52（Asia/Shanghai），覆盖 IGA/IBRA、trimmed/immersed IGA，NURBS、B-spline、T-spline、THB-spline、LR-spline，局部加密、切割单元、连续性、参数域映射、边界条件、积分与稳健性，以及结构动力学、壳/实体、接触、断裂、多物理场、拓扑优化、GPU/并行、预条件、ROM 和 AI/神经算子。GeoPDEs、PetIGA、tIGAr、igatools 未发现窗口内正式发布；G+Smo 有开发修复但无正式版本。

工作/状态方法与量化开放性与局限FreeCAD 迁移实验
非线性 IGA 梁 FSI 映射
预印本；Kratos 实现声明		Bernoulli/Timoshenko NURBS 梁到独立流体界面的构形相关映射，转置保证功共轭。p=2/3、4/16/64 knot spans、60°弯曲与 4π 扭转下，有限差分虚功误差最低约 10−11–10−10；Timoshenko 映射对 p=2/3/4 呈约 3/4/5 阶。给出 Mok、Turek–Hron、Goland benchmark；未给 OCCT/STEP 导入、trim、接触、墙钟/内存。控制点不是物理点，Frenet frame 在零曲率处失效，需要 frame transport。从 OCCT NURBS 中心线提取 knots/weights/control points 与材料 director；对同一湿表面检查位移 RMS、虚功差、反力和时步能量漂移。
NURBS-enhanced 高阶 FV
预印本		曲壁 NURBS + k-exact 重构 + dGRP 黏性通量。在 Couette 41,344 cells、k=3 时，速度 L2 误差从 polygon 的 4.626×10−5 降到 3.493×10−7，NURBS 路径约四阶；线性重构无 dGRP 不收敛。测试为 2D 层流与混合网格；无 trim surface、3D 壳/实体、接触或开源代码链接；Newton/GMRES 参数较强，几何收益与求解器收益需拆分。以圆环、椭圆环、带孔板做 OCCT 精确曲线、Gmsh 高阶曲边与线性 faceting 三组；固定 flux/BC，分别量化几何误差、收敛阶与迭代数。
HB/THB 代数粗化
预印本；GeoPDEs 实验		局部反演 refinement matrix，不组装 mass matrix/数值积分；残差给无未知常数的 L∞ 界。11,223 DOF 六级自适应路径上单次局部转移把 H1 误差放大 1.22 倍，global L2 projection 为 1.18 倍；误差界 effectivity 2.9–7.7，典型步保持 56% 域完全不变。移动前沿细网 24,432 DOF，参考同精度网 15,906 DOF。二维立方 maximal-smoothness HB/THB；没有真实 CAD trim、多 patch continuity、条件数、墙钟或并行数据。全局投影更准，连续多次粗化在最粗两级可把误差放大到约 2.5 倍。用带移动载荷的 NURBS 梁/壳，记录 DOF、误差界、真实能量误差与粗化区域；与重新网格的 CalculiX 对照，验证载荷/BC 不随参数域映射漂移。

G+Smo 开发侧，PR #910 修正 containingSides() 对面、边、角返回错误方向；另有 gsGeometry::refineCoeff 与 Greville API 重命名。这些是开发修复，不是正式 release。它们提示边界枚举和局部加密 API 会直接影响 Dirichlet/Neumann 边的可追踪性，应在 FreeCAD 导出的每个 face/edge 上保留双向映射和方向断言。

结论：本周证据支持“精确曲壁、高连续基和局部粗化在特定 benchmark 上有数值优势”，不证明 OCCT B-Rep 的 trim/pcurve/多 patch 连续性能被这些实现无损接收。生产前仍要完成控制点、节点矢量、权重、修剪边界、seam、orientation 与连续性保真核查，并与 Gmsh/CalculiX 的传统 FEM 使用相同材料、载荷和边界条件复算。

AI × CAD/CAE

本期优先筛选能迁移到 FreeCAD、可复现且有量化验证的工作。以下结果均为作者报告；在固定几何 kernel、网格、单位、切分和硬件上复现前，不视为生产保证。

工作/状态方法、数据与量化开放性、局限/失效模式工作流影响与验证
CAD-derived 虚拟拆解
预印本		按共同释放约束把紧固件组成操作集，用可见性、工具可达性、扭矩移除、路径与物理验证生成 AND/OR 图。54-component OpenManipulator gripper 上，可见性/可达性筛掉 51.4% 候选；受控 toy assembly 未见 branching violation。论文公开，未发现代码/数据仓库；仅一个复杂装配案例，未覆盖弹性变形、公差、螺纹咬合或传感误差。置信度中。将 FreeCAD Joint/BOM/fastener 属性映射到图；对每个拆解动作保存碰撞、工具包络、约束释放与再装配证书，并用随机紧固件缺失/遮挡做失效测试。
MechFoundry agentic CAE
预印本		从对象描述生成形状、载荷案例、材料，使用非贴体 adaptive octree differentiable GPU solver 做非线性响应与优化。50 个日常/工程对象平均 6.5 min、US$1.3/对象。关键工程判断由语言模型 reviewer 评分，没有测试套件或实验真值；几何、BC、材料和模型假设可共同错但求解仍收敛。代码开放性不足，置信度低–中。只迁移“提案生成”，不迁移自动放行；FreeCAD 中要求每个载荷/支撑落到命名拓扑，单位、材料来源、接触与安全系数由规则和 CalculiX 双检。
能量范数 FE surrogate
预注册预印本；代码/数据开放		线弹性中离散势能 gap 等于应力误差能量；只换 loss，3D transformer 中位 energy-norm error 降 7.5×、von Mises error 降 6.1×，2D von Mises 误差减半以上。label-free energy 模型距监督能量模型仅 1.3×。代码、配置、记录与数据有版本/Zenodo；代码为非商业许可证。无网络能迁移到显著更细网格；Ritz projection 除 peak stress 外更准，峰值和网格 OOD 仍危险。置信度高。把 CalculiX stiffness/load 导出为筛查证书；按 energy gap、von Mises tail、反力平衡和网格加密一致性排序，不以 displacement MSE 放行。
Ms-LegONet
预印本；代码/生成器/权重开放		学习局部 coefficient-dependent zero-boundary space，以共享 interface traces 和递归 static condensation 组合。256 个高对比 primitive 的 2D mosaic 上 L2 error 比基线低 4–150×；2D 新系数快 1.6–2.3×；3D 多查询 port response 快 30–900×，相对误差 10−4。系数类内泛化，不等于任意 CAD/接触/塑性；3D 结果依赖 exact local space 与 port 设定。开放性好，置信度中高。先在重复材料胞元、梁/支架子结构做组件级 ROM；每个 primitive 保存局部 Céa 指标，越界材料、裂纹、接触或几何拓扑变化自动回退全阶。
PhysICL 非结构网格场预测
预印本		单一 checkpoint 从 K 个已标注仿真上下文直接预测任意 query mesh 场与 quantile。5 个未见 PLAID 数据集上 K≥32 时均优于最近邻；AhmedML 中位 110 万节点、K=64 峰值 GPU 4.27 GiB；几何/载荷 procedural fine-tune 把 stress error 降 2.7×。在低秩场上落后专用 ROM；按数据集训练的 Transolver 仍可更准 2.8–9.9×。未见明确代码发布，置信度中。作为参数扫描预览与异常检测，不替代求解；用 32/64 个 CalculiX 案例做 context，检查 quantile calibration、峰值应力尾部、mesh/拓扑 OOD 与守恒。

范围覆盖判断：Text-to-CAD、programmatic CAD、CAD copilot、constraint solving 与可验证装配，本周没有比上期原生 FreeCAD benchmark 更强的新量化结果；不得重复旧成果充数。本期新增主要落在 agentic CAD/CAE、装配理解、载荷/边界条件提出、surrogate/ROM/neural operator 与后处理不确定性。自动参数化、拓扑优化、AI 辅助网格、参数标定、PINN、digital twin 与异常检测均检索过，但没有同时满足窗口、量化、开放性和 FreeCAD 可迁移性门槛的新条目。

CATIA 与 Rhino / STEP / 3DM 互操作

CATIA/商业产品侧未发现窗口内可核验的公开 release 或工程 benchmark，本期记为本周无重要变化，不以产品营销声明代替证据。rhino3dm 则有明确开发变化：PR #752 为 Python 3.12+ 构建单一 abi3 wheel，但明确不支持 free-threading；41/43 CI checks 通过，尚不是正式 release。PR #753 新增 Python/JavaScript/.NET 对 8.35 的性能回归门禁，覆盖文件 I/O、表迭代、BRep、mesh、SubD、Draco/JSON 等；本地阈值 1.5×、CI 1.75×，这是“不得退化超过阈值”而不是性能提升证明。

对 FreeCAD/OCCT—Rhino/3DM—STEP 链，建议用同一真值件同时核对 NURBS degree/poles/knots/weights、trim curve 与 pcurve、closed/periodic/seam、edge orientation、实例变换、颜色/层级/名称和单位；分别保存 exact geometry 与 display mesh 的 hash，避免把 tessellation 一致误当成 B-Rep 保真。

Gmsh 与 meshio

Gmsh 本周无正式 release，但主线合并了大规模实验性 discrete CAD modeler：71 个文件、约 2.1 万行新增，含 primitive、boolean、fillet、triangle-soup import、shape recognition 与 API 示例；广义 winding number 用 dipole-moment tree 评估 triangle soup 内外。它面向离散几何修复/建模，不会恢复原始 NURBS 设计意图，也没有可引用的精度/墙钟 benchmark；对 FreeCAD 应只作为 mesh-derived 候选，不得覆盖 OCCT 精确几何。

polytope 路径继续补齐：API 可按元素返回 edge/face 计数并验证输入；读取、分区、ghost、梯度、共享面与导出限制也有防护。Web 端新增 WASM64 最高 16 GB memory，普通 WASM32 仍为 4 GB。验收应包括凹/薄 polyhedron、>127-node face、>231 tag、共享反向面、分区合并与 MSH/VTK/MED 往返 hash。meshio 在固定窗口内未发现 commit/release，记为本周无重要变化。

VTK 与 ParaView

ParaView 6.2.1 于 11 月 11 日正式发布，是本期少数稳定发布。它基于 VTK 9.7.2，修复 DPvtk 多时间步/内存泄漏/并行错误传播、composite dataset 全局 point/cell ID、VTKHDF temporal cache、IOSS 错误报告、大网格整数溢出和 Python 数千 array 查找的二次复杂度等。Clip 的 static-mesh cache 在早期 benchmark 中建缓存一轮约 2.5×慢，后续约 0.7×时间，约 5 个 time steps 才回本；6.2.1 提供 Use Cache 开关。这一量化可直接指导短序列后处理。

VTK 主线开发把 polyhedron face 允许共享并用负索引表示反向，同步更新 VTKHDF 2.9、XML 2.5、ghost utilities 及 OpenFOAM/CGNS/FLUENT/CONVERGE readers。它不是正式 VTK release。验证要同时比较 face orientation、cell volume/centroid、ghost 拓扑、array 与并行 rank 不变性；特别注意旧 reader/writer 对新 face 语义的兼容。

CalculiX 与 Abaqus-compatible 流程

CalculiX 作者仓库本周没有正式 release。窗口内只有 flowoutput.f 变更和错误/警告消息改进，没有 release note、review 或量化 benchmark，证据不足以建议升级。Abaqus-compatible 工作流仍应固定已验证的 ccx 版本，保存输入 deck、二进制与编译器哈希；对候选主线只跑小型回归：静力、模态、接触、温度/流固输出、FRD/DAT 解析、能量/反力平衡与 Abaqus 关键字差分。

Python / C++ / pybind11 / ABI

pybind11 PR #6198 于 11 月 12 日合并 stable ABI 支持：CPython 3.12+ 的 abi3 与 3.15+ free-threaded 的 abi3t 目标是每个平台各用一个 wheel 覆盖后续 Python。作者报告 awkward 一个 microbenchmark 下降 1–3%，其他测试不可测或部分更快；这仍是主线开发，不是 v3.1.0 正式能力保证。ABI 仍受 NumPy、跨模块类型、exception translator、holder/lifetime 与解释器模式影响。

FreeCAD 插件不应立即切 abi3。建议矩阵：FreeCAD 内置 CPython 版本 × regular/free-threaded × Debug/Release × MSVC/clang-cl × NumPy on/off × pybind11 stable/unstable ABI；跑导入、跨模块类型识别、对象寿命、异常、析构、sub-interpreter、长时批处理与保存重开。rhino3dm 的“abi3 但禁用 free-threading”同时说明各依赖的 ABI 边界必须分开声明。
