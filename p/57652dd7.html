CAD/CAE 生态周报｜2026-11-02

发表于2026-11-02|更新于2026-11-02|CAD/CAE 生态周报
|字数总计:7.8k|阅读时长:19分钟|阅读量:

定位：面向 FreeCAD 动力学自动化工作流。

检索窗口：2026-10-26 08:49 至 2026-11-02 08:49（Asia/Shanghai）。本期只把窗口内可核验的官方预发布、合并提交、开发提交、论文原文与问题单列为动态；正式发布、开发中变更、预印本、产品声明、社区信号和“本周无重要变化”分级标注。

执行摘要

本周最值得做的是把“装配事务—STEP 精确几何—分区网格—多面体结果—模态语义”串成一条可复算的数据契约。FreeCAD weekly-2026.10.28 仍是开发预发布，但 Assembly 已合并防止爆炸视图任务重入把临时位移写回真实装配的修复；STEP/IGES 在非英文界面丢失颜色的路径也已修复并回移 26.3 分支。Gmsh 开发分支加速分区写出、登记 HXT 边界恢复产生的 Steiner 点，并修复混合 built-in/OCCT 实体 tag 冲突。VTK 开发分支加入分布式单文件 VTKHDF 写出，并继续修正 polyhedron 边/面语义；CalculiX 修正 C3D8R 热结果并补强输入检查。AI 侧只有 CAD-WAM 达到“新提交、量化、代码开放、可形成 FreeCAD 验证”的优先门槛：其 DeepCAD 7,962 模型统一评测中无效率 0.666%、IoU 0.964、平均 Chamfer 1.142，但模型只覆盖最多 10 步草图—拉伸序列，且训练依赖 8×H800。IGA 专项在固定窗口内没有合格的新发布或论文，不能用 10 月 21 日的壳拓扑优化预印本冒充本周新闻。

  • 为 Assembly 爆炸视图建立“任务打开—重复双击—取消—保存—重开”回归，比较零位姿漂移、事务栈和约束残差。
  • 用非英文 UI 的带色 STEP、修剪 NURBS 与重复实例建立互操作真值集，并贯通 Gmsh 分区写出、VTKHDF/VTK 多面体和 CalculiX 结果哈希。
  • 只在隔离分支复现 CAD-WAM：把 DSL 映射到 FreeCAD/CadQuery 后，追加参数扰动、拓扑命名、STEP 往返和可验证装配门禁。

本周最优先的 3 项行动

  1. 封住装配任务重入。在 RC2、weekly-2026.10.28 和含修复的开发构建中，对同一装配重复双击 Exploded View；取消后要求所有 Placement 与基线逐项相同，保存重开后关节残差不变，并把命令事务数量纳入断言。
  2. 建立颜色、精确几何和结果格式的跨语言真值链。在中文/韩文 UI 导出含面颜色、层级、实例与修剪 NURBS 的 STEP；核对颜色、控制点、节点矢量、权重、pcurve/修剪环，再对 Gmsh 分区 MSH、CalculiX FRD/DAT 和 VTKHDF 做实体、面列表、数组、单位与 SHA-256 差分。
  3. 把 AI 输出当候选程序而不是正确 CAD。复现 CAD-WAM 的统一指标后，再加入 FreeCAD 特有判据：BRepCheck、拓扑命名稳定、全约束草图、参数扰动重算、装配约束闭环和 STEP 二次导入；未通过者不得进入动力学求解。

FreeCAD Assembly 自动化与 API/插件变化

weekly-2026.10.28 是 10 月 28 日发布的官方开发测试构建，发布页明确“不用于生产”。本周最直接的 Assembly 修复是 PR #32497：当 Exploded View 任务已打开时再次双击，旧行为会重建任务界面、重新施加爆炸位移，并可能把活动 create/edit 事务提交，导致临时平移写入真实装配；取消只能撤销最新事务。修复在任务对话框已激活时直接返回，并已回移 26.3 分支。

证据边界：这是已合并开发变更，PR 只报告手工验证，没有随提交展示自动化位姿/事务回归。对无头或批处理工作流，建议记录双击前后每个零件的 4×4 Placement、活动命令数量、关节残差和 FCStd 哈希；取消、保存重开和再次进入编辑都必须无漂移。该修复不等于 Assembly Python API 稳定承诺，插件仍应固定 FreeCAD tag、Python/Qt/OCCT/VTK 组合。

同时，问题 #33978 是需谨慎对待的社区信号：macOS ARM64 上 CalculiX DAT 已有有效固有频率，但部分 FEM Result 的 EigenmodeFrequency 仍为 0，且出现“Values need to be unique”。报告者修改导入脚本后新建模型成功，但未完成原文件的受控前后对比，因此它不是已确认根因或修复。验收应同时比较 DAT、FRD、Result 对象标量和保存重开后的模式序号。

IGA / CAD–分析一体化

本周无重要变化。检索边界为 2026-10-26 08:49 至 2026-11-02 08:49（Asia/Shanghai）：检查了 IGA、IBRA、trimmed/immersed IGA、NURBS/B-spline/T-spline/THB-spline/LR-spline、局部加密、切割单元积分、连续性和参数域映射，以及结构动力学、壳/实体、接触、断裂、多物理场、拓扑优化、并行/GPU、预条件、ROM 和神经算子。G+Smo 的 dev 最后公开提交为 10 月 1 日；PetIGA、tIGAr、GeoPDEs 与 igatools 均未发现窗口内正式版本或提交。窗口外 10 月 21 日的 NURBS 壳拓扑优化预印本不作为本周新闻重复。

验证对象量化指标本期结论下一实验
OCCT/STEP NURBS次数、控制点、节点矢量、权重、参数域、Hausdorff/法向误差无新证据可改变基线FreeCAD 导出—再导入逐字段差分
修剪/切割单元环闭合、短边、负 Jacobian、积分失败率、条件数无窗口内量化工作孔/缝/近切曲面的小型真值集
结构动力学自由度、收敛阶、频率/振型误差、组装/求解时间、内存无合格新 benchmarkIGA 对 Gmsh 二次单元—CalculiX 模态
ROM / neural operator域外误差、守恒、端到端墙钟、加速比没有兼具窗口日期、开放性和精确 CAD 传递的新结果冻结几何/材料/载荷后盲测

面向 FreeCAD 的门禁保持不变：从 Geom_BSplineSurface 提取 pole、knot、multiplicity、weight 和 u/v 参数域，从 TopoDS_Face 提取 3D edge、pcurve、内外 wire 与方向；再与 Gmsh/CalculiX 传统 FEM 在相同材料、载荷、边界条件和几何容差下比较位移、反力、模态、能量、自由度、条件数、时间和内存。没有这些数据，就不能把“精确 CAD 几何”推断为“精确分析模型”。

AI × CAD/CAE

本期只纳入有 benchmark、量化结果、开放实现且能形成 FreeCAD 验证实验的工作。其他条目即使营销声量更大，也不替代物理和几何门禁。

工作/状态方法与数据量化结果开放性、局限与风险FreeCAD 验证
CAD-WAM
10 月 29 日预印本		Qwen2.5-1.5B 生成操作级 DSL；SetVAE 编码实际中间实体，辅助头预测下一几何状态；每步由 CadQuery/OCCT 执行后反馈。DeepCAD 178,238 模型，统一评测 7,962 个测试模型。无效率 0.666%；平均/中位 CD 1.142/0.166，IoU 0.964，Euler 匹配 95.850%；相对最强任务基线，CD 中位数降 15%、均值降 56%。状态预测头把无效率 0.779%→0.666%、平均 CD 1.316→1.142。代码开放。数据只含 1–10 步草图/拉伸，零拔模；训练/评测用 8×H800，编码器会圆化细边；生成器与评测 kernel 环境不同，布尔近重合面仍敏感。复现统一指标后，追加 OCCT BRepCheck、拓扑命名、全约束草图、参数扰动、STEP 往返、装配约束和动力学可解性；对失败尾部做分层统计。
DIP-CAD v3
10 月 27 日修订预印本		VLM agent + CAD kernel；显式面/边/点引用、局部坐标桥与草图约束保留设计意图；GERD-EVL 与 DeepCAD 子集。静态生成 mIoU 提升 11.1%/5.6%；参数编辑 mIoU 提升 7.0%/4.2%。本周只是旧预印本修订，不是新同行评议结果；arXiv 页面未确认代码/数据发布。mIoU 不能证明拓扑命名、约束闭合或长参数链稳定，置信度中低。用 FreeCAD Expression/Spreadsheet 驱动 20 次参数扫描；统计重算成功率、约束自由度、引用漂移和最终 B-Rep 差分。

范围覆盖结论：CAD-WAM 覆盖 Text-to-CAD、programmatic CAD 和 kernel-in-the-loop 生成；DIP-CAD 覆盖 agentic CAD、几何引用、约束与自动参数化。二者都不是成熟的 CAD copilot，也没有验证多零件装配、接触或动力学。几何理解/修复、拓扑优化、AI 辅助网格、边界条件/载荷识别、参数标定、solver acceleration、ROM、surrogate model、PINN、neural operator、digital twin、后处理和异常检测在固定窗口内没有同时满足新鲜度、量化、开放性和 FreeCAD 可迁移性的成果；因此明确记为“本周无合格新增”，不拿旧论文填充。主要失效模式是训练分布外特征、边/面引用漂移、指标掩盖少数灾难性输出、kernel/tessellation 版本耦合，以及高算力复现成本。

CATIA 与 Rhino / STEP / 3DM 互操作

FreeCAD PR #33922 是本周最实用的互操作变更：非英文 UI 重新应用语言时，STEP 导出模块从 ImportGui 退回 Import，导致“STEP with colors”静默变成无颜色导出；IGES 类型名变更后 GUI 仍查旧名，也使颜色丢失。提交者在韩文 UI 中做了导出—导入验证，修复已合并并回移 26.3 分支。

这是颜色/模块选择修复，不是 NURBS 或修剪保真的量化证明。建议在中文、韩文、英文 UI 下对相同 FCStd 导出 STEP AP214/AP242，并比较 shape 数、实例层级、颜色绑定、面方向、控制点、节点矢量、权重、修剪环、体积与质心。CATIA 与 rhino3dm 在窗口内没有可独立核验的重要正式发布；商业材料仅按产品声明处理，3DM 网格单精度与 NURBS 精确曲面应分开验收。

Gmsh 与 meshio

Gmsh 官方仓库的公开镜像显示三类开发变化。分区写出提交把重复线性查找改为有序集合的二分查找，但没有随提交给出时间/内存 benchmark；必须用 10²–10⁴ 分区和稀疏实体 tag 实测。HXT 边界恢复把新 Steiner 点登记到所属曲线/曲面，避免保存时缺少 tag。混合几何 tag 修复防止 built-in 实体 tag 与 OCCT 布尔新实体冲突，旧行为会丢 volume 或使绘制崩溃。

此外，MSH4 合并现在接受多个解文件重复写入整张网格的 overlap，并避免重复登记边界。所有条目均为开发提交，不是正式版本。验证应比较分区前后实体/物理组/ghost/overlap、Steiner 点归属、总单元数、体积、Jacobian、写出时间、峰值内存和文件哈希。meshio 在窗口内没有提交或 release；不得假定它已覆盖上述新语义。

VTK 与 ParaView

VTK 开发分支为 vtkHDFWriter 增加 UseExternalDistributed，并配套简单分布式非结构网格的单文件测试；后续提交从子文件复制数据类型。其意义是 MPI 结果可收敛为一个 VTKHDF 入口，但还需要测试多 rank、空 rank、不同数组类型、失败恢复、写入时间和峰值内存，不能只凭“文件能打开”验收。

多面体侧新增 vtkUnstructuredGridSides，并让 polyhedron 的边从 face 列表读取、比较时忽略边顺序。XML MultiBlock reader 修复无 index 与嵌套 block 的读取。ParaView 则为 Clip 增加可关闭 static mesh optimization 的选项，并从 release 默认配置撤回 VisRTX-for-ANARI。它们都是开发状态；后处理回归需验证 block 路径、cell/face stream、数组 tuple 数、时间步、截图像素和 CPU/GPU 渲染差异。

CalculiX 与 Abaqus-compatible 流程

CalculiX 作者仓库在窗口内修正 C3D8R 的热结果计算：resultstherm.f 对 C3D8R 调用 hourglass 相关形函数路径；另有 C3D8R 热 hourglass 控制、C3D8I selective mass scaling、Johnson–Cook UMAT 修正和额外输入检查。MTU patchset #304 合并 PaStiX 6.4 兼容、CMake 构建与时间戳文档等工程改进。

这些不是正式 release，也没有统一量化 benchmark。应对单 C3D8R 立方体做恒定/线性温度场、约束热膨胀和 hourglass 能量检查，对 C3D8I 显式动力学比较总质量、稳定时间步与能量；Abaqus-compatible 关键词只表示输入语法路径，数值等价需要反力、温度梯度、应力、能量和收敛历史逐项复算。FreeCAD #33978 的模态导入问题要单独跨 macOS ARM64、Windows 和 Linux 验证。

Python / C++ / pybind11 / ABI

pybind11 本周没有正式 release，但开发分支继续减少对 CPython 私有结构的依赖：traceback 格式化改用属性和公开的 PyFrame_GetCode/PyFrame_GetLineNumber，thread state改用 PyThreadState_GetInterpreter；目标是靠近 stable ABI，但 PyPy 7.x 仍保留字段访问回退。实例注册竞态修复则保持可能执行用户代码的 holder 注册顺序。

这不代表 FreeCAD 当前可以直接切 abi3。插件矩阵应固定目标 FreeCAD Python、MSVC/clang-cl、Debug/Release、pybind11 与 NumPy 版本，跑并发导入、跨模块类型识别、异常 traceback、析构、sub-interpreter 和 free-threaded 实验构建；同时用 ASan/TSan 或 Windows Application Verifier 检查竞态与 UAF。任何 wheel 变化都要重跑 FCStd 保存重开和长时批处理。

来源与证据边界

本期联网核对 FreeCAD、Gmsh、meshio、VTK、ParaView、CalculiX、pybind11、rhino3dm、G+Smo、GeoPDEs、PetIGA、tIGAr 与 igatools 的官方发布、提交、PR 或问题，并查阅 arXiv 论文原文和公开代码。FreeCAD weekly 是预发布；Assembly、STEP/IGES、Gmsh、VTK、ParaView、CalculiX 与 pybind11 条目均为开发状态；CAD-WAM 与 DIP-CAD 是预印本；FreeCAD #33978 是尚待确认的社区问题信号；IGA、CATIA、rhino3dm 和 meshio按固定窗口明确记录“本周无重要变化”。所有提交或论文指标在本地 FreeCAD—Gmsh—CalculiX—VTK 工作流复现前，都不是生产收益保证。
